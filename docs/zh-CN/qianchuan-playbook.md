# 千川自动化投放方法论

这份文档讲投放团队怎么把千川日常操作拆成规则。公开版只给通用打法和示例阈值，团队落地时要结合类目、客单价、毛利、退货率和履约成本重新校准。

## 一、先把计划分层

自动化规则要按计划状态执行，不能让所有计划吃同一套阈值。

### 冷启动计划

目标是拿样本。系统主要观察消耗、点击、成交、ROI 和素材表现。冷启动阶段建议减少强动作，多做提醒和轻量止损。

可用动作：

- 消耗达到观察线后进入判断
- 长时间无成交时提醒
- 明显亏损时暂停
- 有成交且 ROI 达标时进入放量池

### 放量计划

目标是稳定扩大成交。系统要看 ROI 是否持续达标、成交是否有连续性、预算是否被提前打满。

可用动作：

- ROI 达标且成交稳定时阶梯加预算
- 加预算后设置冷却时间
- 一天内限制加预算次数
- 加预算后重新观察，不连续追高

### 控成本计划

目标是守住亏损线。预算动作要谨慎，停投动作要快。

可用动作：

- ROI 低于下限且消耗达到观察线时暂停
- 单计划连续亏损时停止继续加预算
- 商品维度亏损时暂停同商品相关计划
- 每天归位到保守预算

### 恢复计划

目标是验证计划还能不能继续跑。恢复时先用小预算观察，避免刚恢复就吃掉大额消耗。

可用动作：

- 只恢复有过成交记录的计划
- 恢复后进入独立观察窗口
- 观察窗口内不加预算
- 再次亏损时重新暂停

## 二、用“观察窗口”减少误杀

千川计划会有短时波动。规则要等到样本够了再动作。

常见观察条件：

- 最少消耗：例如达到基础预算的一定比例
- 最少运行时间：例如新计划运行一段时间后再判断
- 最少成交数：适合放量判断
- 最少点击数：适合冷启动判断
- 冷却时间：一次动作后等待一段时间再评估

系统里可以把这些条件放进规则字段：`afterMinutes`、`cooldownMinutes`、`dailyCap`、`hold`。

## 三、规则动作优先级

同一轮执行里，动作要有优先级。建议顺序：

1. 风险止损
2. 商品级停投
3. 计划暂停
4. 预算归位
5. 阶梯加预算
6. 提醒和记录

暂停动作命中后，本轮不再对同一个计划做加预算。这样能减少“刚判定风险，又继续放量”的冲突。

## 四、预算归位

预算归位适合每天固定时间执行。它解决的是计划经过一天多次调整后，次日需要回到可控预算起点。

建议做法：

- 不同投放类型设置不同归位预算
- 小于平台允许修改幅度的差额直接跳过并记录
- 跳过、成功、失败都写入审计日志
- 归位结果发到团队通知渠道

示例：

```text
放量类计划：归位到较低测试预算
控成本计划：归位到保守预算
已暂停计划：只记录，不自动恢复
差额过小计划：跳过，避免平台拒绝
```

## 五、低 ROI 停投

低 ROI 停投是最常见的自动化动作。它要同时看消耗和时间，避免计划刚启动就被误停。

建议条件：

- 运行时间达到观察窗口
- 消耗达到最低样本线
- ROI 低于阈值
- 当前没有人工保护标记

建议动作：

- 暂停计划
- 写入操作日志
- 记录触发指标
- 给团队发送摘要

## 六、高 ROI 加预算

高 ROI 加预算要分阶段。一次加太多会改变流量结构，也会让复盘失去参照。

建议条件：

- ROI 高于目标线
- 成交数达到最低要求
- 预算消耗速度稳定
- 距离上次加预算超过冷却时间
- 当天加预算次数没有超过上限

建议动作：

- 按固定步长或比例加预算
- 记录加预算前后的预算
- 记录触发时的 ROI、消耗、成交数
- 进入冷却期

## 七、商品维度停投

同一个商品可能被多个计划同时推广。只看单计划容易漏掉商品整体亏损。

建议按商品聚合：

- 商品总消耗
- 商品总成交
- 商品 ROI
- 涉及计划数
- 连续亏损天数

当商品连续亏损时，可以暂停该商品下的相关计划，并给出“商品级”原因。这样复盘时能看到问题来自商品、素材、出价还是计划结构。

## 八、日报复盘

自动化系统每天要留下能复盘的证据。

日报建议包含：

- 今日同步计划数
- 命中规则数
- 暂停计划数
- 加预算计划数
- 预算归位成功数
- 平台拒绝或跳过原因
- 商品级风险列表
- 需要人工复查的计划

复盘重点：

- 自动化节省了哪些重复操作
- 哪些规则误伤
- 哪些规则太保守
- 哪些商品需要人工判断
- 哪些阈值需要调小或调大

## 九、agent 使用边界

coding agent 适合读报表、写复盘、检查规则、生成测试和维护代码。它不应该直接拿到写入接口。

建议边界：

- MCP 只读连接报表库
- 写入动作由本地控制台和后端规则执行
- 所有规则变更需要管理员账号
- 所有 API 调用写入审计日志
- 生产 token 不进入 prompt、文档或公开仓库

这样可以让 agent 帮忙分析，又能把投放动作留在受控系统内。
